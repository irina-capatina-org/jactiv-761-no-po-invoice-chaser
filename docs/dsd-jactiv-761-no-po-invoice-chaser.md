## 1. Solution Overview

The no-po-invoice-chaser-api is a scheduled API Workflow that queries Coupa daily for draft/new invoices with no linked purchase order (past 7 days, excluding credit notes), counts them, and sends a Slack summary to AP staff if any are found. On clean days (zero invoices), the run completes silently with no Slack message. Delivered as a single API Workflow project within solution `no-po-invoice-chaser-761`, triggered Monday–Friday at 10:00 AM Romania time. Read-only; no records created or modified.

| Component | Type | Entry Point | File |
|---|---|---|---|
| no-po-invoice-chaser-api | API Workflow | Schedule (10:00 EET/EEST weekdays) | `code/no-po-invoice-chaser-761/no-po-invoice-chaser-api/Workflow.json` |

## 2. As-Built Architecture

The solution contains one stateless API Workflow project that executes the complete flow in a single sequence: compute a 7-day lookback window, query Coupa via HTTP GET, filter and count invoices, conditionally compose and send a Slack Block Kit message, validate the response, and return execution status.

```
Schedule (10:00 EET/EEST weekdays)
  ↓
Workflow.json: Sequence
  ├─ Compute date window (JavaScript)
  ├─ HTTP GET Coupa invoices
  ├─ Filter & count (JavaScript)
  ├─ Branch: count > 0?
  │  ├─ [yes] Compose Slack payload → HTTP POST Slack → Validate → Set flag
  │  └─ [no] Exit silent
  ├─ Log result (JavaScript)
  └─ Return status, count, sent flag
```

**Connections:** HTTP Request activity routes through `uipath-uipath-http` connector to Coupa (`uipath-coupa-coupa`, connection ID `5fadfc73-a372-46ae-a27c-2481741eed07`) and Slack (`uipath-salesforce-slack`, connection ID `43d506f7-7de2-4798-aac1-9522e2e45dbb`). Both exist in Orchestrator test environment as integration services; connection resources are pre-deployed in `code/no-po-invoice-chaser-761/resources/solution_folder/connection/`.

**Variables:** `windowStart`, `windowEnd`, `runDate` (strings, YYYY-MM-DD), `qualifyingCount` (number), `exclusionLog`, `slackPayload`, `coupaUrl` (strings), `slackSent` (boolean, tracks if Slack POST succeeded).

## 4. Exception and Error Handling

No retry logic or fallback paths implemented. All errors cause immediate termination and Orchestrator job failure alert.

| Error ID | Condition | Handler | Result | Retry |
|---|---|---|---|---|
| S1 | Coupa HTTP timeout or 5xx | None; HTTP_Request_Coupa fails | Job failed; no Slack sent | No |
| S2 | Coupa response missing `invoice-type` or `invoice-lines` field | `Javascript_FilterAndCount` throws (line 215) | Job failed; no Slack sent | No |
| S3 | Slack response `ok` ≠ true | `Javascript_ValidateSlack` throws (line 373) | Job failed; logged | No |
| S4 | HTTP_Request_Slack non-200 | Connector error | Job failed | No |
| S5 | Credential unavailable at runtime | Connector auth fails | Run blocked before start | No |
| S6 | Unhandled JavaScript error | Activity throws | Job failed; logged | No |
| B3 | Zero qualifying invoices | Branch condition false (line 270), Else arm executes (line 409) | Exit silent; status=Successful, count=0, slack_sent=false | N/A |

## 5. Operations Runbook

### Trigger & Schedule
**Type:** Orchestrator schedule; **Frequency:** Monday–Friday 10:00 AM Romania time (EET/EEST); **Manual start:** Orchestrator UI, no arguments required.

### Expected Runtime
Single HTTP round-trip to Coupa (~200ms typical) + optional Slack POST (~300ms if invoices found) = **300–500ms normal case**; up to **1 second if Coupa slow**. Timeout not specified; Orchestrator default applies.

### Normal Run Output
- **Clean day (count = 0):** Console logs `qualifying_count=0` and `slack_sent=false`; returns `{"status":"Successful","qualifying_count":0,"slack_sent":false}`. No Slack sent.
- **Found invoices (count > 0):** Console logs `qualifying_count=<N>` and `slack_sent=true`; returns `{"status":"Successful","qualifying_count":<N>,"slack_sent":true}`. Slack DM delivered with Block Kit header, invoice count, no-PO-no-pay policy explanation, "Open in Coupa" button (date-filtered URL), and footer showing date window and check timestamp.
