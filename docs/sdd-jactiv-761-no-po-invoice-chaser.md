## 1. API Workflow Overview

Weekday-scheduled API Workflow querying Coupa for invoices with no linked PO (draft/new, past 7 days, excluding credit notes, per BR-01), counting them, and sending one Slack DM to Irina Capatina (`WLX9BD8FN`) with count, no-PO-no-pay explanation, and filtered Coupa URL. Read-only; no records created/modified (BR-10). No message on clean days.

**Trigger:** 10:00 AM Monday–Friday, Romania time  
**Scope:** Status draft/new, invoice date ≤ 7 days, no linked PO, not credit note  
**Outcome:** One Slack DM or silent; run logged

## 2. Input Schema

No external inputs; triggered by schedule.

| Field | Type | Required | Description |
|---|---|---|---|
| (none) | — | — | Schedule-triggered, no arguments |

## 3. Output Schema

| Field | Type | Description |
|---|---|---|
| `status` | string | "Successful" (including clean days); error → Orchestrator alert |
| `qualifying_count` | number | Count of invoices: draft/new, ≤7 days, no linked PO, not credit note |
| `slack_sent` | boolean | true if count > 0 and Slack sent; false if count = 0 or error |

## 4. Execution Flow

| Step | Activity | Inputs | Outputs | Notes |
|---|---|---|---|---|
| 1 | Workflow start | schedule | variables init | No external inputs |
| 2 | Compute date window | none | `windowStart`, `windowEnd`, `runDate` | JavaScript: today − 7 days (YYYY-MM-DD); used in query and footer |
| 3 | HTTP GET Coupa | dates | invoice array | Status draft/new, date ≤7 days (BR-04), limit 50 ([ARCHITECT REVIEW] pagination ~194) |
| 4 | Filter and count | array | `qualifyingCount`, log | JavaScript: exclude credit notes (BR-03, B1), exclude linked PO (BR-02, B2), count (BR-05) |
| 5 | Branch: count > 0 | count | true/false | Zero → exit silent (BR-07, B3); non-zero → send Slack |
| 6 | Compose Slack payload | count, dates | `slackPayload`, `coupaUrl` | JavaScript: Block Kit header/section/button/footer; coupaUrl with date filters |
| 7 | HTTP POST Slack | payload | response | DM to `WLX9BD8FN` (BR-06); Block Kit formatted |
| 8 | Validate Slack | response | ok or throw | Check response.ok (S3) |
| 9 | Log result | count, sent | console | Run observability |
| 10 | Return | all vars | status, count, sent | Success on all paths; error → exception |

## 6. Error Handling

No retry, fallback or recovery (BR-08, BR-09); failures terminate immediately.

| Failure | Detection | Response |
|---|---|---|
| Coupa timeout/5xx/element missing (S1, S2, S4) | HTTP ≠ 200 or field missing | Log; fail; no Slack |
| Slack non-200 or response.ok = false (S3) | Validation step | Log; fail; no retry |
| Credential unavailable (S5) | Connector auth fails | Orchestrator error; run blocked |
| Unhandled exception (S6) | JavaScript or activity error | Logged; failed |

Clean day (zero invoices): succeeds silently (BR-07, B3).

## 8. Testing Strategy

### Happy path: qualifying invoices and Slack sent

| Assertion | Method |
|---|---|
| Coupa returns invoices; credit notes excluded | Log exclusion records; verify credit notes absent |
| Invoices with linked PO excluded | Verify only no-PO invoices in count |
| Count correct; Slack DM received with Block Kit, button, dates | Check Slack history; verify title, section, button URL correct |
| Response: status=Successful, count>0, slack_sent=true | Verify response JSON |

### Business exceptions

| Condition | Assertion |
|---|---|
| Zero invoices (B3, BR-07) | status=Successful, count=0, slack_sent=false; no Slack sent |
| Credit note (B1) | Excluded; in log; omitted from count |
| PO text only, no link (B2, BR-02) | Counted as missing PO; included in count |

### System errors

| Failure | Assertion |
|---|---|
| Coupa timeout/5xx (S1, S4) | Run fails; logged |
| Coupa field missing (S2) | Throws; fails |
| Slack non-200/ok=false (S3) | Validation throws; fails |
| Credential missing (S5) | Connector error; run blocked |
| Unhandled script error (S6) | Logged; failed |
